# 上位机算法方案设计

## 硬件平台分析

| 硬件 | 型号 | 关键参数 |
|------|------|---------|
| GPU | RTX 3060 Laptop | 6GB GDDR6, 3840 CUDA Core, FP16 吞吐 10.9 TFLOPS |
| CPU | R9 5900HX | 8C/16T @ 3.3-4.6 GHz, Zen3 架构 |
| RAM | 32GB DDR4 | 双通道 3200MHz |

### 平台约束

- **显存瓶颈**：6GB VRAM 是多模型部署的核心约束，需严格控制模型参数量，所有推理必须使用 FP16
- **CPU 优势**：8C/16T 可承担并行预处理（图像解码、几何变换、传统图像处理）
- **内存充裕**：32GB 足够缓存多帧历史数据、加载全部模型权重

## 二、模块详细设计

### 2.1 目标检测 → YOLOv8s

**选型理由**：RTX 3060 上 FP16 推理可达 ~100 FPS，mAP@50 = 44.9，2200 万参数，VRAM 占用约 50MB，为后续模块预留充足显存。

| 项目 | 选择 |
|------|------|
| 模型 | YOLOv8s (ultralytics) |
| 参数量 | ~22M |
| 显存占用 (FP16) | ~50 MB |
| 推理速度 (RTX 3060) | ~100 FPS |
| mAP@50 | 44.9 |
| 部署方式 | ONNX Runtime + CUDA EP, FP16 |

**推理流程**：

1. RGB 图像 `resize → 640×640 → normalize`
2. `session.run()` 获取 `[batch, 84, 8400]` 输出
3. NMS 后处理 (置信度 ≥ 0.5, IoU ≥ 0.45)
4. 输出 `[x1, y1, x2, y2, confidence, class_id]`

**模型转换**：

```
PyTorch (.pt) → ONNX (opset=17, dynamic batch) → ONNX Runtime FP16
```

### 2.2 缺陷检测 → 传统+深度学习混合

采用"快速筛查 + 精确分割"两级流水线：

```
┌──────────────────┐     ┌─────────────────────┐     ┌──────────────────┐
│  传统 OpenCV 快速  │ ──→ │  YOLOv8s 缺陷检测    │ ──→ │  U-Net 像素级分割 │
│  (形态学+Canny)   │     │  (缺陷分类+粗定位)    │     │  (精确轮廓/面积)  │
│  ROI 提取         │     │  置信度过滤          │     │  仅可疑区域触发   │
└──────────────────┘     └─────────────────────┘     └──────────────────┘
```

#### 2.2.1 传统 OpenCV 快速筛查

适用于规则纹理、高对比度缺陷（划痕、凹坑、裂纹）：

- 高斯滤波 `(5,5)` → 自适应阈值 → 形态学闭运算
- Canny 边缘检测 → 轮廓提取 → 面积/周长过滤
- 利用**深度图辅助**：在深度不连续区域优先标记为疑似缺陷

#### 2.2.2 U-Net 像素级分割

仅对 YOLOv8 检测到的可疑 ROI 触发，节约推理开销：

| 项目 | 选择 |
|------|------|
| 模型 | U-Net (ResNet-34 编码器) |
| 参数量 | ~24M |
| 显存占用 (FP16) | ~200 MB |
| 推理速度 (RTX 3060, 256×256) | ~40 FPS |
| 部署方式 | ONNX Runtime FP16 |

### 2.3 6D 姿态估计 → 基于 PnP 的轻量级方案

**选型理由**：PnP（Perspective-n-Point）算法利用已知的三维模型点与图像中检测到的二维关键点之间的对应关系求解相机位姿，无需大型神经网络模型，可在 CPU 上高效运行。结合双目系统输出的深度图，无需额外训练数据，对新型工件只需更新 CAD 模型即可快速部署。该方法特别适合工业场景中工件种类多、换型频繁的需求。

**核心思路**：利用双目系统 SGM 算法输出的高精度视差图，结合已知工件的三维 CAD 模型关键点，通过 PnP 求解器直接获取 6D 位姿。

| 项目 | 选择 |
|------|------|
| 方法 | PnP (EPnP + RANSAC) |
| 关键点检测 | ORB / SuperPoint 特征匹配 or 语义关键点检测 |
| 3D 模型来源 | 工件 CAD 模型离线提取关键点 |
| 深度来源 | FPGA SGM 模块输出的视差图 → 深度图 |
| 显存占用 | ~0 MB (CPU 上运行) |
| 推理速度 | ~5-15 ms |
| 部署方式 | OpenCV solvePnP / Eigen + 自定义求解器 |

**处理流程**：

```
YOLOv8s 检测工件 → 2D ROI
    ↓
在 ROI 内检测二维关键点 (ORB/SuperPoint 匹配)
    ↓
从 CAD 模型获取对应三维关键点坐标
    ↓
从视差图查询每个关键点的深度 → 三维坐标 (u, v, d)
    ↓
PnP 求解器 (EPnP + RANSAC) → 输出 (R, t)
```

**关键步骤说明**：

1. **关键点检测**：每个工件预定义 N 个模型关键点（如角点、孔中心等显著几何特征），通过 ORB 特征匹配或训练轻量级 KeypointNet 在 ROI 内定位关键点的 2D 像素坐标。
2. **深度查询**：对每个检测到的 2D 关键点 `(u, v)`，从 FPGA 输出的视差图中读取对应位置的深度值 `d`，利用相机内参 `K` 反投影为相机坐标系下的三维坐标 `p_cam`。
3. **PnP 求解**：已知 N 组 3D-2D 对应关系 `{(P_model_i, p_cam_i)}`，使用 EPnP 算法求解初始姿态，再以 RANSAC 迭代剔除误匹配点，最终通过非线性优化（Levenberg-Marquardt）精化位姿。

**优势**：
- 几乎不占用 GPU 显存，所有计算在 CPU 上完成
- 对新型工件只需提供 CAD 模型，无需重新训练
- 单帧处理 5-15ms，远快于基于学习的方案 (~30ms)

### 2.4 多模态融合策略

根据 `upper_computer_algorithms.md` 调研结果，本项目采用**中期融合 + 晚期融合混合策略**：

- **缺陷检测**：RGB 通道注意力 + 深度图空间注意力（LCA 思想），在特征层面融合
- **姿态估计**：基于特征匹配的几何融合，PnP 利用 2D 图像关键点 + 深度信息 + CAD 模型先验联合求解
- **目标检测**：RGB 单模态（YOLOv8s），深度图作辅助后过滤

```
RGB ──────────→ CNN Backbone ──→ RGB Feature ──┐
                                                  ├──→ Cross-Attention ──→ Fused Feature
Depth ────────→ CNN Backbone ──→ Depth Feature ─┘
                                     │
IR ───────────→ 独立推理通道 ──→ 温度异常检测 ──→ 独立报警
```

**IR（红外）图像处理**：红外与 RGB 波段差异大，不适合直接特征级融合。采用独立推理通道，输出温度异常区域后与 RGB 检测结果在决策层关联。

## 三、显存预算与管理策略

### 3.1 显存分配 (6GB VRAM)

| 组件 | VRAM 占用 | 说明 |
|------|----------|------|
| YOLOv8s (ONNX FP16) | ~150 MB | 含运行时开销 |
| U-Net (ONNX FP16) | ~300 MB | 按需加载 |
| PnP 姿态估计 | ~0 MB | CPU 上运行，几乎不占显存 |
| 系统开销 (CUDA context 等) | ~500 MB | |
| 输入/中间张量缓存 | ~450 MB | 640×640 / 256×256 |
| **合计** | **~1.4 GB** | 6GB 余量非常充裕 |

### 3.2 显存优化策略

- **惰性加载**：U-Net 仅按需加载，YOLOv8s 常驻显存
- **CUDA Stream 复用**：预处理 CUDA Stream + 推理 CUDA Stream 独立，避免竞争
- **共享 Backbone**：YOLOv8s backbone 特征图可复用给 U-Net（可选优化）

## 四、多线程流水线架构

```
Thread 1 (数据采集):     FPGA → 环形缓冲区 (ring buffer, 16 帧)
Thread 2 (预处理):       取帧 → 视差转深度 → RGB/IR 配准 → 归一化 → 入推理队列
Thread 3 (推理主控):     取预处理帧 → 调度模型推理 → 结果入后处理队列
Thread 4 (后处理+GUI):   结果解析 → 叠加显示 → PyQt6 渲染
```

| 队列 | 类型 | 容量 | 说明 |
|------|------|------|------|
| `raw_queue` | `collections.deque` | 16 | 原始帧缓冲 |
| `preproc_queue` | `queue.Queue` | 8 | 预处理后帧 |
| `infer_queue` | `queue.Queue` | 4 | 待推理帧 |
| `result_queue` | `queue.Queue` | 4 | 推理结果 |

## 六、部署流水线

```
1. 模型训练 (云端/工作站)
   YOLOv8s 自定义数据集训练 → best.pt
   U-Net 缺陷分割训练 → unet_best.pt

2. 模型导出
   YOLOv8s:   pt → ONNX → onnx-simplifier → FP16 ONNX
   U-Net:     pt → ONNX → onnx-simplifier → FP16 ONNX

3. 关键点配置 (PnP 姿态估计)
   工件 CAD 模型 → 提取三维关键点坐标 → 存入配置文件
   可选用 SuperPoint 离线渲染训练关键点检测器

4. PC 端部署
   pip install onnxruntime-gpu opencv-python pyqt6 ultralytics
   加载 ONNX 模型 → CUDA EP → 推理
   PnP 求解调用 OpenCV solvePnPRansac (CPU)
```

## 七、性能预估

| 处理阶段 | 预估耗时 (ms) | FPS |
|----------|-------------|-----|
| 数据采集 (FPGA→PC) | 2-5 | 200-500 |
| 预处理 (视差→深度+配准) | 3-5 | 200-333 |
| YOLOv8s 推理 (ONNX FP16) | 8-10 | 100-125 |
| 缺陷检测 (传统) | 2-3 | 333-500 |
| 缺陷检测 (U-Net, 按需) | 20-25 | 40-50 |
| PnP 姿态估计 (CPU) | 5-15 | 66-200 |
| 后处理 + GUI 渲染 | 5-8 | 125-200 |
| **端到端延迟 (含姿态)** | **~30 ms** | **~33 FPS** |
| **端到端延迟 (仅检测)** | **~20 ms** | **~50 FPS** |

**结论**：在 RTX 3060 Laptop + R9 5900HX 平台上可稳定实现 33 FPS 全功能流水线（检测+缺陷+姿态），满足工业实时性需求。

## 八、扩展性考虑

| 场景 | 建议 |
|------|------|
| 需要更高检测精度 | 升级 YOLOv8s → YOLOv8m (VRAM +100MB, FPS 降至 60) |
| 需要更强姿态估计 | PnP 关键点匹配升级为 SuperPoint + SuperGlue 端到端匹配，或引入 KeypointNet 学习关键点 |
| 对称工件处理 | PnP 中引入对称性先验，对对称轴投票融合多解 |
| 需要更多相机通道 | 在采集线程增加通道，推理层复用模型（耗时线性增长） |
| Intel CPU 平台部署 | 全部模型导出 OpenVINO IR，利用 iGPU 加速 |
